Understanding React Server Components

Mar 04, 2025·6 min read·React

Server Components let you render parts of your UI on the server and send only the result to the browser. They can read data directly, and they ship no JavaScript to the client.

The rule of thumb: start on the server, and move to the client only when you need state or event handlers.

A simple example

Here is a component that reads posts on the server. It is just an async function.

app/posts.tsx
export default async function Posts() {
  const posts = await getPosts(); // runs on the server
  return <List items={posts} />;
}

When to reach for the client

Add "use client" at the top of a file when the component needs useState, effects, or browser APIs. Everything it imports becomes part of the client bundle, so keep those files small.

Links look like this. The thin bar at the top of the page tracks reading progress.

Server and client components can be mixed freely. A server component can render a client component and pass it serializable props, which keeps most of the tree on the server while interactive leaves hydrate on their own.

That split is the main idea. Most of the page stays static and cheap, and only the parts that need to move pay for JavaScript.
